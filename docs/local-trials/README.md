同一份体验包收到的意见追加到当轮反馈。交付下一份候选包时，在目标版本下新增 `round-02` 等目录，并在表中登记。每轮指南记录程序内嵌版本、源提交和清单 SHA-256。相同操作可引用前一轮指南，本轮写明变化和需要复测的条目。

用户结束本轮反馈收集后，核对问题编号，以一个文档 PR 归档。随后在修复迭代的 `spec.md` 定范围、`design.md` 记确认方案、`plan.md` 跟踪修复与验证。每个问题的 PR 及用户本地验收按[体验反馈修复流程](../iterations/README.md#体验反馈修复)执行。计划内修复合并后，从 `main` 构建下一轮候选包。

复测时链接原反馈编号，记录所用轮次和结果，保留首次遇到问题时的描述。正式发布使用用户最终确认的那一轮文件。[发布流程](../iterations/06-release-upgrade/release.md)
