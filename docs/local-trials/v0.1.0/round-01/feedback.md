# v0.1.0 第 1 轮体验反馈

截至 2026-11-27，第 1 轮反馈收集暂告一段落，共六项。用户已在 Windows 体验 CLI 和 Codex，并确认使用 `connect` 返回的 Session ID 后，CLI 能成功发送交易。同事已在 macOS 配置 MCP 后体验 Codex，首次使用时遇到的问题见第 6 项。[本轮指南与候选校验信息](guide.md)

## 1. Session ID 格式错误时只显示 usage

**已复现。** 在 Windows 运行 `transaction send --session-id aaa`，同时传入有效的收发地址和 `--chain-id 71`，CLI 打印整段用法并退出 2。用户无法判断缺少参数还是输入有误。期望提示具体字段、所需格式，以及从哪里取得有效 ID。

## 2. 发送交易时需要手动传入 Session ID

**暂缓。** 用户提出让 `transaction send` 支持省略 `--session-id`，随后确认本轮继续要求显式传入。使用 `connect` 返回的 ID 已能成功发送交易。等 CLI 帮助和错误提示改进后，用户会再次体验，再决定是否需要简化。

## 3. Windows 终端找不到指南中的 codex 命令

**已定位，有临时用法。** 本机安装了 Codex 桌面版，内置 CLI 所在目录未加入用户或系统 PATH。用户在配置 MCP 时卡在 `codex mcp add`，平时使用 Git Bash。通过桌面版安装目录可找到 `codex.exe`，PowerShell 已验证可调用。期望指南提供从 Git Bash 定位和调用 CLI 的步骤。

## 4. Windows 体验指南缺少 Git Bash 命令示例

Windows 用户也会使用 Git Bash。指南应补充用 Git Bash 运行 Windows 候选程序的示例。本轮以 Git Bash 实测结果为验收依据，WSL 免测。

## 5. CLI 命令行诸多问题反馈

在体验 CLI 的时候，遇到以下问题：

1. 运行 CLI 时（不带任何参数），会打印所有命令的 Usage，但是每个命令都没有文字说明功能作用；
2. 每个命令的 Usage 里，支持的参数没有描述信息，且可选参数的默认值也不知道是什么；
3. 命令执行失败时，用户难以从输出中判断原因。期望报错指出哪一步失败、为什么失败，以及可以怎样处理。例如第 1 项的无效 Session ID，应提示出错的参数和取得有效 ID 的方式。

可以考虑成熟的 CLI 框架去实现所有命令，例如：cobra，这样 CLI Usage 会比较清晰，格式也统一。

## 6. 其他用户 Codex 首次体验不流畅

在 MacOS 系统上下载 wallet-bridge-darwin-arm64 后，能成功的运行 version 命令查看版本。然后，在 codex 页面上顺利配置好 bridge wallet 的 MCP 插件后遇到几个问题：

- 首次使用时，页面提示需要浏览器授权。需要转到 CLI 完成这一步，对不熟悉命令行的用户有门槛。改进方式留到修复迭代讨论。
- 同事在 macOS 的 Codex 对话里看到了“连接钱包”链接。点击后，Bridge 页面在 Codex 内置浏览器中打开。
- **已确认的目标。** 由用户点击 Codex 中的审批链接，在装有钱包插件的系统默认浏览器中继续处理同一请求。

## 本地核对（2026-11-27）

- **第 3、4 项。** 已在 Windows Git Bash 中调用候选 `.exe` 查看版本，并通过桌面版安装目录找到 Codex CLI、运行 `--version`。
- **第 5 项。** 已用 v0.1.0 复现。无参数运行显示各命令的用法；`transaction send --help` 列出参数和单位，省略金额时实际采用的默认值则需要查阅指南或代码。验收时可直接检查命令用途、参数释义、必填项及默认行为。Cobra 是实现建议。
- **第 6 项。** 连接和交易两个 MCP 工具都会返回审批链接。同事已确认连接链接的实际打开位置。后续需验证 Codex 对话中的链接能否交给系统默认浏览器打开，并在该浏览器继续处理同一请求。
