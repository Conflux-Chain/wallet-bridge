## 2. 迭代完成要求

- 本轮范围、预期行为和适用环境已明确；影响本轮实现的待定项已处理或显式移出本轮。
- 当前范围实现完成，适用的构建、检查和关键行为验证已执行，结果可以复现。
- 各 PR 按当轮计划分步交付，范围、依赖、评审状态与验证证据可追溯。
- 演示步骤、已知限制和验证证据已记录；实际钱包／agent 尚未验证时明确标注。
- 已实现、已通过自动验证、已通过真实环境验证、用户已验收分别记录；未收到用户验收结果不能标为已验收。
- 用户反馈的未通过项记录为遗留问题，说明是否阻止下一轮及原因。

## 3. 证据记录方式

各轮 plan 记录关联 A-ID、环境、版本、操作／命令、预期与实际结果及限制；较长报告单独保存并链接。通过[当前迭代](iterations/current.md)进入活动轮次，历史证据保留在原轮次目录。

钱包实际签名广播和 agent 兼容性需要真实环境证据。模拟钱包测试只证明模拟条件下的行为；client 查询 receipt 可用于验证端到端结果，不改变 Bridge 服务职责。

基础文档准备只验证文档链接、来源与状态一致性，不构成功能或用户验收。
