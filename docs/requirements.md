# Wallet Bridge 首版需求确认稿

确认日期：2026-11-18；支持环境与首版交付范围于 2026-11-19 补充。本文作为接口及详细设计的产品依据，不表示设计已同步或功能已实现。

## 1. 产品边界

**Bridge 服务尽量简单、职责单一，只负责本地 client 与浏览器钱包之间的钱包桥接。**

首版包括：连接钱包、建立固定账户与网络的 Session、桥接交易审批及发送、回传钱包结果、必要的请求管理与活动日志。

| 职责 | 归属 |
|---|---|
| 连接钱包、核对账户和网络、协调钱包操作 | Bridge |
| 业务交易构造、余额、allowance、报价和滑点等 | Client |
| 查询 receipt、执行结果、确认数、finalized | Client；Bridge UI 跟踪留待后续 |
| 持续扫描链上状态 | 不属于 Bridge 服务首版职责 |
| personal_sign、typed sign 等消息签名 | 后续迭代，首版不包含 |

## 2. 面向的 client 与交付方式

首批支持范围（2026-11-19 用户确认）：

| 项目 | 范围 |
|---|---|
| 操作系统 | Windows 10+、macOS 13+ |
| 原生 CPU 架构 | Windows amd64；macOS amd64／arm64 |
| 浏览器 | Chrome |
| 钱包 | 首版验收 MetaMask 和 Fluent；按 EIP 标准自动发现兼容钱包，供用户选择 |
| 运行位置 | CLI、local HTTP 服务、agent（首批 Codex）与浏览器在同一台机器运行 |

WSL／容器等兼容范围待细化；目标系统、Chrome 与钱包版本的实际兼容性在对应迭代验收。

自动发现以向当前页面暴露的标准 Provider 为范围；验收名单不作为品牌白名单。Fluent 沿用现有 EVM／Conflux eSpace 范围验收。

普通用户从本仓库 GitHub Releases 下载对应平台的独立程序，无需预装 Node.js、npm、Python、Go 或 Rust 工具链。[发行与版本选择](iterations/06-release-upgrade/spec.md#首次获取与版本选择)

Bridge 提供统一可执行程序，包含 CLI 和 local HTTP 服务能力。不同语言的 client 可以调用该程序确保服务就绪，再直接访问 HTTP；各语言 SDK 是可选封装，不是使用前提。

服务在当前操作系统用户的私有数据目录自动管理运行数据；凭据无需用户单独下载或手动创建，使用方式见[本机服务访问凭据](local-credentials.md)。单一程序交付不表示运行时没有数据文件。

首版同时附带可供 Codex 使用的 MCP Server，由统一可执行程序的子命令启动。CLI、HTTP、MCP 均提供连接、交易请求及查询／取消等通用桥接入口。

| Client 类型 | 接入与交互要求 |
|---|---|
| 一次性 CLI | 首次需要钱包时接入；默认打开浏览器并打印链接，可阻塞等待结果 |
| 交互式 CLI | 首次需要钱包时接入，后续复用；等待期间可取消 |
| AI agent／MCP Server | 首次钱包 tool 调用时接入；返回链接供用户点击，通过异步查询取得结果 |
| 桌面应用 | 用户使用钱包功能时接入；打开装有钱包扩展的外部浏览器，应用保持响应 |
| 本地脚本 | 按需接入；默认可取得链接，是否自动打开、阻塞或异步由调用方选择 |

页面打开策略可由调用方选择，不按 client 类型写死。基础流程不强制注册 client；长期应用身份和授权管理留待后续。

多个 client 共享服务。同一系统用户主动运行的本地 client 视为可信，共用一份自动管理的服务凭据；请求／Session 用 UUID 定位，不使用独立资源凭据，不承诺 client 间安全隔离。浏览器管理页仍需独立授权，统一查看和审批请求；请求 ID 不授予审批权限。此结论于 2026-11-20 确认，替代原资源凭据隔离方案，见 D-034。

用户从本机 CLI 或 Codex 发起操作时，Bridge 应在当前流程中完成所需的服务访问。首次使用或浏览器授权到期后，连接钱包、发送交易、查看活动记录均无需另行执行 `wallet-bridge ui` 或向 agent 确认浏览器授权。连接同意与钱包发送确认仍由用户完成，查看历史无需连接钱包。该体验已确认，交付进度见[迭代 7 计划](iterations/07-round-one-feedback/plan.md)。

浏览器的完整管理授权自签发起固定有效 30 天，可跨服务重启复用并可撤销。仅含请求 ID 的地址只用于定位。用户可将 CLI 或 Codex 提供的完整审批链接复制到同机其他浏览器配置，在原期限内处理这一笔请求。查看其他历史或管理其他请求需要独立的访问权限。

## 3. 服务接入与常驻

- 使用固定 `http://127.0.0.1:<port>` origin，所有 client 共用同一个服务。
- Client 按需执行幂等的启动／就绪检查能力；已运行且兼容时直接复用。
- 未运行时自动启动，等待服务真正就绪后才返回成功；有明确的等待超时和错误。
- 使用操作系统互斥锁与固定端口独占监听。锁由常驻服务持有；并发启动时允许短暂存在候选进程，但只有一个有效服务。
- 端口被其他程序占用时明确报错，不随机换端口，不抢占其他程序。
- 服务独立常驻，不随某个 client 退出而停止；用户可主动停止，系统退出或升级时可停止。无需强制开机启动。
- 接入服务不等于连接钱包，也不自动打开钱包页面。

## 4. 版本兼容与升级

程序发行版本与 HTTP 接口兼容性分别判断。接口及所需能力兼容时复用；不兼容时明确反馈，不在普通接入过程中强制替换服务。

用户主动升级时：先下载并校验新版本，保存到独立版本目录；有连接或交易操作等待钱包处理时默认暂缓。安全切换时暂停新请求、保存状态、停止旧服务，在同一固定端口启动新版。失败可回退旧版本及兼容的数据状态。

统一记录当前启用版本，旧 client 配套的旧程序不能静默降级共享服务。切换后 client 重连，页面重新核对版本和请求状态；不自动重新发送交易。仅等待链上确认的已广播交易，在结果已保存且页面可恢复时，不必阻止升级。

## 5. 连接钱包与 Session

| 项目 | 已确认要求 |
|---|---|
| chainId | Client 必须指定，UI 始终显示 |
| chainName | Client 可选提供；未提供则查询 Bridge 内置的常见 EVM 网络名称映射 |
| 名称优先级 | Client 提供名称优先，否则使用内置映射；均未知时只显示 chainId |
| 网络匹配 | 只按 chainId 判断；按需引导钱包切换，不允许用户随意修改 client 的目标网络 |
| 不支持的网络 | 明确提示，不报告连接成功；基础连接不要求 RPC、原生币、区块浏览器配置，不包含自动添加网络 |
| 账户选择 | 首次由用户选择；钱包若授权多个账户，UI 再明确本 Session 使用的一个账户 |
| Session 绑定 | 成功后固定钱包、一个账户与一个 chainId，不可修改；换钱包须新建 Session（2026-11-20 用户补充确认） |

默认映射包括 Conflux eSpace 主网 `1030`、Conflux eSpace Testnet `71` 及常见 EVM 网络。网络名称仅用于显示。

已有钱包对 bridge origin 的授权可以复用，但不能直接视为用户已同意本次应用连接。页面需要展示应用名称及账户、网络要求；自报名称不等于已认证身份。

连接完成前重新核对钱包实际账户和网络，成功结果包含 Session 标识、账户地址、chainId 和可选名称。各 client 可阻塞等待或异步查询同一结果。

2026-11-20 补充确认：完成必要的钱包授权／切链后，页面展示最终钱包、单账户与目标网络，由用户点击“同意连接”才建立 Session。连接请求在钱包操作期间被取消或到期，迟到成功也不再建 Session，需新建连接；钱包已发生的变化不自动回滚。该规则不改变交易已发送后的结果处理。

钱包、账户或网络变化不改变 Session。继续操作前应引导切回；用户需要换钱包、账户或网络时新建 Session，由 client 重新准备业务数据及交易。

## 6. 交易创建与审批

- Client 引用有效 Session，明确提供与其一致的 `from`、`chainId`，并提供目标、原生币金额、data 等实际交易内容。
- 金额使用明确的最小单位。Gas／费用可选，未指定时由钱包估算并经用户确认。
- 账户、网络或必要参数不匹配时拒绝，不自动替换或修正业务参数。
- 请求创建后，待审批交易内容固定；client 修改交易须取消原请求并创建新请求。
- 重复创建、重复点击、多个页面及回传重试，应防止重复执行。结果不确定时不自动重发。
- Approve、swap 等多笔交易可共用 Session，但每笔有独立请求和钱包确认。

审批页的信息层级、目标／实际钱包状态、状态修复及主操作见[请求审阅交互设计](approval-flow.md)。地址和 data 可完整查看、复制；网络或发送账户不符时阻止提交。未指定费用交给钱包估算，未知币种不猜测为 ETH。

Client 的自然语言说明与实际交易内容分开展示，不能当作已验证事实。UI 的解码与审批策略是可选扩展，不将业务语义验证扩展为 Bridge 服务核心职责：

首版采用通用原始交易审批；交易解码与严格模式留待后续。

| 策略 | 行为 |
|---|---|
| 通用模式 | 无法解码时明确标注，展示完整原始数据，允许用户手动确认 |
| 严格模式 | 仅允许符合配置支持范围与约束的操作，未知调用阻止发送 |

“已解码”不表示安全；client 不能绕过用户设置的限制。具体解码目录及扩展机制在详细设计中明确，不默认具备所有 DApp 解释能力。

调用钱包前再次核对账户和网络；交易提交携带明确的 `from`、`chainId`。不匹配时暂停，引导恢复，不能修改 Session 或交易继续发送。多个请求协调排队，避免叠加切链、选账户和发送窗口。

同一请求可重新打开原链接；查询和重试不应反复创建新页面。关闭页面不直接等于取消请求。

## 7. 结果及链上跟踪

Bridge 区分等待审批、排队、等待钱包、拒绝、取消、超时、已取得发送结果和结果未确定等状态。具体枚举及错误码在接口设计时确定。

已取得 tx hash 表示“已发送”，不表示执行成功。Client 使用 chainId、hash 和自己的 RPC 查询链上状态；选择等待 hash、receipt 或 finalized 由 client 决定。

UI 链上跟踪留待后续。扩展时可自行查询对应网络 RPC，展示执行结果、确认数和最终确认状态；不能依赖钱包此刻选中的网络。没有可用 RPC 时明确说明。UI 关闭不影响 client 查询，重开后可用保存的 chainId 和 hash 恢复展示。

## 8. 关闭、超时及结果不确定

| 情况 | 已确认处理 |
|---|---|
| Client 正常结束会话 | 显式 close Session；Session 失效，不接受新请求，并清理活跃会话数据 |
| Session 关闭时仍有未交给钱包的请求 | 一并取消，旧页面不得继续提交 |
| Client 异常退出，未 close | 不仅凭进程或 HTTP 连接断开判定取消；按空闲规则回收 |
| Session 空闲 | 没有未完成请求，且连续 5 分钟无 client 访问时自动回收 |
| 连接／交易审批请求有效期 | 从创建起默认 5 分钟；连接遵守 §5 的已确认规则，交易到期取消尚未交给钱包的请求 |
| 请求已交给钱包 | 不能保证撤回；关闭或超时不能直接证明未发送，保留接收结果所需最小信息 |
| 可能已发送但无可靠结果、无 hash | 标记“结果未确定”，持久化活动记录，不声称执行失败，不自动重发或主动查链 |
| 后续收到原请求的 hash | 更新原请求及活动记录，不能丢弃迟到结果 |

Client 可查询已完成结果；结果回传与重试应幂等，防止 ACK 丢失造成重复操作。

2026-11-20 补充确认：Session 关闭或空闲回收后，可信 client 仍可按 ID 查询其失效状态、固定绑定及已完成连接结果，不能继续发起钱包操作。本轮仅 client 查询有效 Session 时续期；查询原连接请求、浏览器查看均不续期，失效后查询不能复活 Session。

## 9. 持久化日志与重启恢复

活动日志仅保存在本机，默认长期保留。用户可按[活动记录规则](iterations/04-collaboration-recovery/spec.md#活动记录)逐条从列表移除已结束请求。关闭、过期和回收 Session 不删除持久化活动记录。日志记录桥接操作及已获得结果，不要求服务持续更新链上状态。

| 重启前数据／状态 | 恢复要求 |
|---|---|
| 未关闭、未过期 Session | 恢复原账户和网络绑定，继续按原空闲规则处理 |
| 未过期、未交给钱包的请求 | 恢复为待审批，重新核对后由用户继续 |
| 已过期请求 | 标记超时，不重置有效期 |
| 已交给钱包、结果不明 | 标记“结果未确定”，不自动重发 |
| 已取得 hash | 保留结果，供查看或恢复 UI 跟踪 |

**恢复数据不等于自动调用钱包。** 用户继续操作时仍须核对 Session、请求和实际钱包状态。
