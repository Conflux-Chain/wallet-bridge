# Wallet Bridge 迭代开发计划

日期：2026-11-18。状态：草案。本文安排顺序，不改变[需求基线](requirements.md)，也不代表功能已实现。

## 1. 迭代安排

| 迭代 | 核心交付 | 开发前补充 | 验收索引 |
|---|---|---|---|
| 0：范围与方案 | 支持矩阵、首版范围、技术栈、打包方案及权限边界 | 操作系统／浏览器／钱包、本地／WSL／容器／远程范围、CLI 与 MCP 交付、目标 agent、可选能力 | 选定组合及后续验收范围 |
| 1：本地服务 | 可执行程序、固定端口、单实例常驻、启动／复用／就绪检查、版本信息、页面入口与基础访问控制 | 端口、数据目录、共享范围、访问凭据、超时及错误行为 | A-01～04 |
| 2：连接与 Session | CLI／HTTP 连接请求、钱包与账户选择、切链、固定 Session、关闭／过期／回收及基础恢复 | 用户同意步骤、多钱包与多页面选择、Session 权限、失效后的查询能力 | A-05～07、11～12、16～17 |
| 3：单笔交易 | 原始交易审批、钱包发送、结果回传、幂等与持久化、不确定结果及迟到 hash 处理 | 交易类型与字段、nonce／部署／仅签名范围、费用修改、确认步骤、幂等标识、等待边界及结果保留 | A-07～16 |
| 4：协作与恢复 | 多 client／Session／页面排队、日志查看与清理、组合异常及完整恢复 | 队列顺序、页面执行归属、钱包卡住后的恢复、日志／结果／去重记录生命周期 | A-04、10～12、14～17 |
| 5：AI agent 接入 | MCP Server、原请求链接、异步查询／取消、Codex 配置与示例 | 沿用迭代 0 的交付范围，细化 tool、agent 交互和输出 | A-18 及复用流程 |
| 6：发布与升级 | 发行包、兼容判断、版本校验、安全切换、数据迁移与失败回退 | 发行渠道、安装／升级入口、校验及备份回退方式 | A-01、03、19～20；全量验收 |

A-ID 见[验收索引](acceptance.md)，具体场景在当轮 spec 细化。依赖顺序为 0 → 1 → 2 → 3 → 4 → 5 → 6；迭代 3 提供 CLI 交易预览，迭代 5 提供 agent 流程，迭代 6 收尾发布。

## 2. 交付时点

- 迭代 1 即验证无需预装开发工具链的打包方式，发布体验在迭代 6 完善。
- 基础访问控制先于钱包操作；Session 与连接恢复随迭代 2 实现。
- 首笔交易即具备必要的持久化、幂等、取消竞争、不确定结果及迟到回传处理；迭代 4 扩展组合场景。
- 每笔交易独立审批，client 自行构造业务交易并查询链上结果；Bridge 的职责沿用需求基线。
- 真实钱包与真实 agent 分别验收；模拟结果不代替真实环境验证。未完成首版要求的版本标明预览范围。

## 3. 后续扩展

2026-11-19 已确认首版通用桥接，以下扩展留待后续；具体范围以需求基线为准。

| 能力 | 前置能力 | 实现前补充 |
|---|---|---|
| UI 链上跟踪 | 单笔交易 | RPC 来源、支持网络、确认／最终确认定义、无 RPC 展示；A-22 |
| 解码与严格模式 | 原始交易审批 | 解码目录与来源、用户策略、未知调用行为及不可绕过范围；A-21 |
| 更多钱包、浏览器和运行环境 | 连接与交易 | 支持矩阵、交互差异与实际验收组合 |
| 长期应用身份与授权 | 基础 client 隔离 | 身份来源、授权范围、撤销与长期凭据 |

消息签名、语言 SDK、业务 RPC 和服务端持续链上监控沿用需求基线的范围。

## 4. 执行与进度

按[迭代工作流](iterations/README.md)补充 spec、必要的 design doc 及多个 PR 的分步计划。只实现当前 PR 范围，逐个验证与评审，最后验收本轮流程。

[当前迭代](iterations/current.md)提供活动轮次与下一步；各轮 plan 维护 PR 状态及验收证据。本路线图不重复维护进度。技术方案与范围明确后再估算工期。
