# 连接核心与存储测试

连接核心已组合 schema v4 的执行领取、钱包交接／回报和受归属保护的连接终态，并接入统一启动／周期维护。client 侧 HTTP 验证见[接口测试指南](connection-http.md)；浏览器执行 HTTP、CLI／页面连接入口尚未接入，无需新增人工浏览器操作。

## 本地验证

前置条件：Windows 或 macOS，安装 [go.mod](../go.mod) 指定的 Go。以下命令在仓库根目录运行，不需要 Node.js、钱包、资金或已启动的 Bridge 服务：

```sh
go test -tags no_web ./internal/app ./internal/store ./internal/service -run '^TestConnection(Core|Maintenance)' -count=1 -v
```

预期 9 组核心／维护测试（含子用例）通过、退出码为 0，验证：

- 创建已保存但响应丢失后，复用 ID 返回原记录；相同链的规范化写法等值，调用方／意图／网络描述变更报冲突。
- 重开数据库后全部连接状态保留；取消／拒绝／到期后的迟到完成不建 Session。
- 并发同意产生唯一 Session，相同绑定回传收敛到同一 ID，不同绑定报冲突；已关闭结果重放不重建、不续期。
- 原连接查询不续期，有效 Session 的 client 查询才续期；关闭后历史仍可查询。
- 服务就绪前标记已过期连接／Session，保留未过期记录和原期限；模拟定时器触发真实周期维护，不等待五分钟。
- 注入 SQLite 维护失败后，原事务回滚、服务释放端口和锁并报告 `storage_error`；移除注入故障后启动可恢复。

此组服务测试使用临时目录和系统分配的测试端口，不占用正式固定端口；不需要先停止正在运行的 Bridge。

完整连接存储回归：

```sh
go test -tags no_web ./internal/store -run '^Test(Connection|Session)' -count=1 -v
```

预期 55 组测试（含上述 3 组核心组合、下述 12 组执行、9 组交接／终态和本次 4 组协调组合测试及子用例）通过、退出码为 0，覆盖：

- 从 v1 授权库及有记录的 v2 库迁移，成功后原授权、全部连接终态、活跃／关闭 Session 保留；复制或表重建后的失败整体回滚。
- 请求与 Session 持久化、大 chainId、毫秒时间及原始期限保留；读取不续期或刷新访问时间。
- 按 ID 查询／访问选定记录、重复与并发创建保护，关闭 Session 后原连接结果仍可读取；不再测试 client 间凭据隔离。
- 数据约束与缺表／损坏列拒绝；取消 Go context 时不写入记录。
- 连接成功与 Session 同时提交；插入／提交失败或 ID 冲突时整体回滚。
- 取消／拒绝后迟到成功不建 Session；恰好到期也不建 Session，期限不重置。
- 相同回传保留原结果，冲突回传不能改写绑定；两个数据库连接并发完成／取消／到期只留下一个终态。
- 仅有效 Session 的 client 访问续期，原始查询不续期；关闭／回收后历史可查、重启或时钟回退也不复活。
- Session 访问／关闭及批量维护的更新／提交失败整体回滚；跨数据库连接并发访问、关闭与到期不会改写固定绑定。
- 执行记录迁移、单执行槽、领取／心跳／中断与显式恢复；具体边界见下节。

## 执行领取与恢复存储

前置条件及工作目录同上；只验证本次新增存储：

```sh
go test -tags no_web ./internal/store -run '^TestConnectionExecution' -count=1 -v
```

预期 12 组测试（含子用例）通过、退出码为 0，覆盖：

- v3 升级保留连接、Session 与浏览器授权；失败整体回滚，修复后可重试；旧迁移器拒绝 v4。
- 两个数据库连接并发领取／恢复仍只有一个执行槽；重试保留原记录，不续心跳。
- 90 秒失联边界、授权失效及显式重启中断；恢复必须使用新执行 ID，旧页面不能再心跳或中断新执行。
- 取消／到期后仍保留未结束的钱包等待；显式恢复只释放终止请求的等待，不改历史结果或新建 Session。
- 更新／提交故障全部回滚；唯一索引、外键及阶段约束继续有效。

测试使用自动清理的私有临时数据库，不占用固定端口或接触正式数据，命令结束即完成清理。无需 Node.js、服务、浏览器或钱包。这组部分阶段数据由 SQL 准备；实际交接／回报方法的存储验证见下节，均不代表真实钱包调用。

## 钱包交接与连接终态存储

前置条件及工作目录同上；只运行本次新增验证：

```sh
go test -tags no_web ./internal/store -run '^TestConnection(Wallet|Guarded)' -count=1 -v
```

预期 9 组测试（含子用例）通过、退出码为 0，覆盖：

- 相同交接重试及跨数据库连接并发只有一个调用许可；调用返回后保留最近 ID，延迟交接或旧回报不能重新调用或结束新调用。
- 页面／心跳／重启中断、授权失效、取消／到期及显式恢复；回报只结束等待，不自动建立 Session 或恢复同意。
- 完成／拒绝检查当前执行、授权及阶段；连接结果、唯一 Session 与执行结束原子提交，重开及关闭后的重放保留原结果。
- 交接／回报、连接／Session／执行写入及提交故障整体回滚；同意与拒绝、取消、钱包交接、回报、撤销及恢复并发竞争。

测试直接调用真实存储方法，使用自动清理的私有临时数据库，无需启动服务或钱包，不占用固定端口或修改正式数据。钱包交接尚无对应 HTTP／CLI／页面入口，因此没有人工钱包操作步骤；协调核心组合见下节，浏览器接入随后验证。

## 协调核心与服务维护

前置条件及工作目录同上，无需 Node.js、已运行的服务、浏览器或钱包：

```sh
go test -tags no_web ./internal/app ./internal/store ./internal/service -run '^TestConnectionCoordina' -count=1 -v
```

预期 9 组测试（含子用例）通过、退出码为 0，验证：

- 核心从已认证主体填入浏览器归属；真实授权、领取／心跳／交接／回报、中断恢复、同意／拒绝及关闭历史组合，撤销后的旧主体不能写入。
- 并发同意复用已提交的唯一 Session ID；大 chainId 及账户规范化，重放无需新随机数且不复活 Session。
- 连接取消及统一维护的逐步写入／提交故障整体回滚；启动恢复先于就绪，心跳／授权／期限失效保留未结束的钱包等待，健康执行不因周期维护中断。
- 维护失败报告 `storage_error` 并释放监听与服务锁；移除测试故障后，原数据重启恢复，期限与钱包等待不重置。

使用真实私有临时 SQLite、模拟时间条件及随机测试端口；命令结束自动停止测试服务并清理数据，不占用正式固定端口，不重启或迁移正式用户数据。这是核心／服务组合验证，未实际调用浏览器钱包。

## 数据与交付边界

数据库位置及保护方式见[本地服务指南](local-service.md#sqlite-存储测试与数据)。新程序启动时会追加 schema v4；仅支持 v1～v3 的程序会拒绝该版本。测试和构建不更新正在运行的旧服务，正式升级按用户授权执行。

连接／Session 不保存访问令牌或摘要，浏览器授权的 cookie 摘要独立保留；本机接入仍使用[统一服务凭据](local-credentials.md)。`closed_at` 表示显式关闭或空闲回收后的失效时间，历史读取不等于允许钱包操作。

新服务在就绪前统一恢复，此后每 30 秒在同一事务内维护连接／Session 期限与执行状态；逐次写入仍检查期限，不因维护间隔延长有效期。启动中断原执行，未结束的钱包等待保留；打开第二个存储连接不会触发恢复。浏览器完成／拒绝走受归属保护的核心方法，浏览器 HTTP／CLI／页面映射待后续 PR；进度与证据统一见[迭代 plan](iterations/02-connection-session/plan.md)。
