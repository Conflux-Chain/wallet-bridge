# 本机服务访问凭据

本文说明迭代 1 的凭据方案，实现进度见 [plan](iterations/01-local-service/plan.md)。前台／后台启动均自动初始化凭据；ensure／status／stop 自动读取所需令牌并先验证服务身份。启动与测试步骤见[本地服务指南](local-service.md)。MCP 接入按后续迭代交付；运行 `version` 或 Vite 预览不会生成正式凭据。

## 用途

这些令牌用于访问 Bridge 本地服务；钱包私钥与助记词始终由浏览器钱包保管。

监听 `127.0.0.1` 只能保证连接来自本机，无法确认调用者的权限。服务需要鉴权，防止其他普通系统用户或未授权调用者读取受保护信息、停止服务或取得浏览器管理权限。Host／Origin 校验与令牌鉴权各自承担不同边界。

| 文件 | 用途 | 权限边界 |
|---|---|---|
| `client.key` | 普通服务接入，以及 CLI 验证端口上是否为本服务 | 不授予停止服务、签发浏览器授权或批准钱包操作的权限 |
| `control.key` | 本机管理命令：停止服务、签发及撤销浏览器授权 | 不自动批准钱包连接或签名 |

同一操作系统用户的 CLI／MCP 共用本机服务；这些令牌不证明独立应用身份。请求／Session 的资源凭据和浏览器管理 cookie 另行控制对应权限，见[访问模型](iterations/01-local-service/design.md#4-本机与浏览器凭据)。

## 用户需要准备什么

用户安装 Bridge 可执行程序；服务首次启动时，程序自动创建私有数据目录和凭据。官方 CLI／MCP 在本机读取所需令牌，用户无需手动创建、下载或将其粘贴给 AI。直接调用 HTTP 的应用需按接口文档提供相应访问凭据。

| 系统 | 自动管理的数据目录 |
|---|---|
| Windows | `%LOCALAPPDATA%\WalletBridge` |
| macOS | `~/Library/Application Support/WalletBridge` |

因此安装包可包含一个程序，运行后仍会有本地数据文件；除凭据外，后续还会有数据库等运行数据。数据独立于可执行文件，正常重启或同机更换程序版本时复用。

## 保存与恢复

- 访问控制是必要能力，受限文件是本版选择的持久化方式。Windows ACL 仅向当前用户及 SYSTEM 赋权；macOS 目录为 `0700`、文件为 `0600`，并检查扩展 ACL。
- 换电脑或换操作系统用户时，各自初始化新的凭据。缺失文件在初始化时补建，已有有效文件保持原值；丢失的旧令牌无法恢复。
- 文件损坏、权限不安全或无法建立必要保护时明确报错，保留原文件；具体用户恢复入口随服务功能交付。
- 凭据不写入仓库、诊断日志或聊天记录。已控制当前操作系统用户账户的程序可以读取其文件，不在隔离承诺内。

文件格式与原子初始化细节见[技术设计](iterations/01-local-service/design.md#pr-1-2凭据文件)，开发验证步骤见 [README](../README.md#本机凭据测试)。
