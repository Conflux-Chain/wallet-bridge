# 本机服务访问凭据

本机接入采用 D-034 的简化模型，实现进度见[当前迭代](iterations/current.md)。前台／后台启动均自动初始化一份服务凭据；CLI 自动读取并验证服务身份。启动与测试步骤见[本地服务指南](local-service.md)。MCP 接入按后续迭代交付；运行 `version` 或 Vite 预览不会生成正式凭据。

## 用途

`client.key` 是唯一的本机服务凭据，用于服务访问、停止及浏览器授权管理，也用于 CLI 验证端口上的服务身份。它不是钱包私钥；私钥与助记词始终由浏览器钱包保管。

监听 `127.0.0.1` 不区分同机的系统用户，也不自动排除普通网页请求。保留一份受系统用户权限保护的服务凭据及 Host／Origin 校验，作为本机接入边界。

同一系统用户主动运行的 CLI／MCP 视为可信，共享服务及管理权限；不隔离各 client，不认证自报应用名称。请求／Session 只用 ID 定位，不分配独立访问凭据，存储迁移见[验证指南](connection-storage.md)。浏览器仍单独授权，每次连接同意和钱包确认按产品流程完成；本机密钥不自动批准请求。

## 用户需要准备什么

用户只需安装 Bridge 可执行程序；服务首次启动时自动创建私有数据目录和 `client.key`。官方 CLI／后续 MCP 自动读取，用户无需创建、下载或粘贴给 AI。直接调用 HTTP 的应用读取同一文件，以 `Authorization: Bearer <token>` 访问受保护接口；详见[Swagger](swagger/swagger.yaml)。

执行 `ui` 后，内嵌页面自动交换一次性链接，浏览器保存 HttpOnly 管理 cookie，服务数据库只保存其摘要；用户无需另外准备授权文件。有效期固定 30 天，刷新或服务重启不延长；页面可退出当前浏览器，CLI 可撤销单个或全部授权。不同浏览器配置、清除网站数据后须重新授权，步骤见[浏览器测试指南](browser-testing.md)。一次性链接含授权权限，仅在显式选择 `ui --print-url` 时输出，不应粘贴到聊天或日志。

| 系统 | 自动管理的数据目录 |
|---|---|
| Windows | `%LOCALAPPDATA%\WalletBridge` |
| macOS | `~/Library/Application Support/WalletBridge` |

因此安装包可包含一个程序，运行后仍会有本地数据文件；除凭据外，服务还会初始化数据库和回滚日志，见[存储测试与数据](local-service.md#sqlite-存储测试与数据)。数据独立于可执行文件，正常重启或同机更换程序版本时复用。

## 保存与恢复

- Windows ACL 仅向当前用户及 SYSTEM 赋权；macOS 目录为 `0700`、文件为 `0600`，并检查扩展 ACL。
- 换电脑或换操作系统用户时，各自初始化新的凭据。缺失文件在初始化时补建，已有有效文件保持原值；丢失的旧令牌无法恢复。
- 文件损坏、权限不安全或无法建立必要保护时明确报错，保留原文件；具体用户恢复入口随服务功能交付。
- 凭据不写入仓库、诊断日志或聊天记录。已控制当前操作系统用户账户的程序可以读取其文件，不在隔离承诺内。

旧目录里的 `client.key` 原样复用；遗留 `control.key` 不读取、不接受，也不自动删除，以便旧程序仍能正常停止旧服务。新安装不生成它。新 CLI 遇到旧服务返回 `incompatible_service`；先用服务配套的旧程序停止，再主动启动新程序，不自动替换运行中的服务。

开发验证见 [README](../README.md#本机凭据测试)和[接入兼容性测试](local-service.md#服务接入兼容性测试)。
