# 迭代 6 · 发布与升级

## 首次获取与版本选择

- **已确认。** 用户从本仓库的 GitHub Releases 下载独立程序。每个版本提供 Windows amd64、macOS amd64 和 macOS arm64 三份产物。程序内嵌审批页，运行环境见[支持矩阵](../00-foundation/spec.md)。
- **已确认。** 下载后可直接运行。需要长期配置 CLI 或 Codex 时，运行一次 `install`，取得当前用户的固定程序路径。此后可删除下载副本。[D-072](../../decisions.md)
- **已确认。** 用户主动检查升级时，默认选择最新稳定版。仅有预览版时提示「暂无稳定版」。用户显式选择预览版后才可安装该版本。[D-067、D-068](../../decisions.md)
- **已确认。** 查询时若显式包含预览版，按语义化版本选出公开稳定版与预览版中最高的一版。当前为 `v1.0.0`、可选 `v1.2.0` 与 `v1.1.0-rc.1` 时，两种查询方式均返回 `v1.2.0`。[D-070](../../decisions.md)

## 首版发布前的用户验收

开发完成后，将候选程序、版本号、校验清单和已验证的体验指南交给用户。用户从首次安装开始，亲自体验 CLI／Codex 接入、连接钱包、审阅交易、查询结果和升级恢复，全程可直接使用独立程序。

用户反馈问题时，修复后提供新的候选版本供复测。用户明确确认该版本可以发布后，才将与验收清单一致的文件发布到 GitHub Releases。预览版也遵循此顺序。[D-069](../../decisions.md)

## 升级时用户看到什么

1. 用户发起升级后，程序先下载并校验目标版本。校验失败时报告原因，原服务继续可用。
2. 钱包被占用时，本次升级结束，显示占用请求。用户处理请求后主动重试。已经取得并保存哈希的交易可在升级后按原请求查询。[D-074](../../decisions.md)
3. 切换期间暂停接收新请求。新版在原地址就绪后，CLI、MCP 与浏览器按原 ID 恢复查询，保留原期限和已记录的结果。失败时恢复兼容的程序和数据。
4. 旧 client 再次接入时，按 API 与能力判断兼容性。停止后再启动服务也应遵循本机启用版本，避免静默降级。[版本兼容与升级](../../requirements.md#4-版本兼容与升级)
5. 旧副本显式执行 `service run` 调试另一版本时，提示已启用程序的路径并退出。普通 CLI 和 MCP 按需后台启动已启用版本。[D-073](../../decisions.md)
6. 服务原已停止时，升级客户端先自动启动本机启用版本。服务恢复原请求并报告就绪后，客户端再检查占用。只有收到停机应答并确认服务锁释放后才可继续。[D-075](../../decisions.md)

## 下载校验

首版以本仓库的公开 GitHub Release 为发行来源。经 HTTPS 读取指定版本的附件信息，先验证 `SHA256SUMS` 与 GitHub 记录的清单摘要一致，再核对当前平台程序的长度、GitHub SHA-256 和清单中的 SHA-256。通过校验且平台匹配的程序才可进入候选版本目录。[D-071](../../decisions.md)

## 升级备份

旧服务停机后，保存本机服务凭据和同一时点的数据库，包括浏览器授权、Session、请求及已记录的交易哈希。备份失败时保留原数据，升级中断时保留本次可用备份。新版开放接单后或旧版回退成功后，自动清理本次备份。[D-076](../../decisions.md)

## 分步确认

升级中断时如何提示和恢复，在切换实现前细化。公开发布、实际已安装服务升级及真实钱包广播的验收状态单独记录。[PR 计划](plan.md)
