# 迭代 3 · 单笔交易

用户通过已有 Session 审阅一笔 EVM 交易，在钱包中确认发送，发起方用原请求 ID 取得结果。本轮交付 CLI、HTTP 与浏览器页面。页面信息与操作沿用[已确认的审阅流程](../../approval-flow.md)，生命周期沿用[需求 §6～9](../../requirements.md#6-交易创建与审批)。

## 创建请求

- 首批支持原生币转账和调用已有合约。代币转账按普通合约调用提交，`to` 为代币合约地址，接收方及数量由 client 编入 `data`。
- 必须提供有效目标地址。缺少或传入空的 `to` 时，在创建阶段返回明确错误，提示本轮暂不支持直接部署合约。用户无须打开浏览器。
- 交易序号由钱包选择。Client 显式传入 `nonce`（含零）时，创建请求即返回不支持该字段的错误。省略时，提交钱包的交易也省略该字段。
- 省略 `value` 按 0 个最小单位处理，省略 `data` 按空字节处理。审阅和交给钱包时使用相同值。
- `gas` 上限可独立提供。费用可留给钱包估算，也可提供传统 `gasPrice` 或成对的 `maxFeePerGas`、`maxPriorityFeePerGas`。两种费用方式互斥，优先费上限不得超过总费率上限。交易类型由钱包选择，显式传入 `type` 即报错。
- Client 明确提供与 Session 一致的 `from`、`chainId`。已创建请求中的交易内容固定。要修改尚待审批的交易，须取消原请求并创建新请求，每笔独立审阅。

### 创建重试与续期

Client 为一次发送生成一个请求 ID，重试时复用。相同 ID、Session、规范化交易、调用方名称和意图返回原记录与原期限，即使 Session 已关闭也能取回。相同 ID 改了内容会报冲突。有意再发一笔相同交易时使用新 ID，单独审批。

成功新建计为一次有效 Session 访问。重试和创建失败均不刷新空闲计时。

### 交接前的取消与到期

按 ID 查询交易只读取进度，请求和 Session 均不续期。到达创建起五分钟的期限即为「已到期」，完成时间取原期限。此前显式取消或关闭 Session 则为「已取消」。再次查询、创建重试或取消均返回已生效的状态与时间。关闭 Session 时逐笔判定，已完成的请求保留原结果。

### 钱包弹窗与重启

交易页已取得执行权并完成切链后，在用户继续核对金额、收款地址等信息期间保留占用。其他连接或交易可以查看进度，须等待本次审阅结束才能操作钱包。交接前取消、到期或页面中断时，如果没有尚未返回的钱包调用，可以放行下一项。

连接与交易共用一个钱包执行槽。交易已交给钱包、Bridge 重启且尚未收到结果时，其他连接和交易都须等待。原钱包调用返回，或用户在原交易页确认「已处理钱包弹窗」后，才可处理下一项。手动放行保留原交易的「结果未确定」状态和接收迟到 hash 的能力，原请求不能再次发送。

## 验收

| 场景 | 可观察结果 |
|---|---|
| 创建与幂等（A-07、10） | 参数与 Session 不符、目标缺失或显式提供 nonce 时拒绝创建。同一次创建的重试可取回原请求和期限，用户有意再发一笔相同交易时能独立审批 |
| 页面与钱包（A-07～09） | 可核对真实参数、来源和调用方描述，复制完整地址与 data。钱包或账户未就绪、网络不符时提示修复。用户点击确认后，只有固定钱包收到本笔发送请求 |
| 取消与期限（A-11、12） | 在交给钱包前，取消、到期或关闭 Session 会阻止发送。未完成请求保护 Session 免于空闲回收。重开普通链接可查看原进度 |
| 结果与恢复（A-13～16） | 有 hash 时返回已发送。交接后丢失结果时保留未确定记录，重启及查询不会再次发送钱包请求。迟到 hash 可更新原记录，关闭 Session 后结果仍可查 |
| 钱包兼容（A-09） | 分别记录模拟 Provider 的调用次数／故障结果，以及 MetaMask、Fluent EVM 的真实测试网发送和 client 独立查链结果 |

## 按开发顺序细化

| 检查点 | 需要决定的用户行为 |
|---|---|
| 钱包能力 | 本轮发送路径调用钱包签名并广播。仅签名并返回原始签名交易的需求单独界定 |
| 钱包交接 | 钱包拒绝发送后原请求如何结束，哪些错误可以判定未发送 |
| 请求查询 | CLI 的等待／退出码与异步查询，结果未确定时给用户的下一步 |
