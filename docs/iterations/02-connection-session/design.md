# 迭代 2 技术设计草案

状态：2026-11-20，PR 2-1～2-2b 已合并，PR 2-3a1 实现生命周期存储，其余方案随对应 PR 细化。本文沿用[既定架构](../../architecture.md)，不增加模块层级；待定产品行为见 [spec](spec.md)。

## 模块边界

| 模块 | 本轮职责 |
|---|---|
| `internal/app/` | 连接请求与 Session 流程、权限、状态转换、期限及执行协调；定义所需存储接口 |
| `internal/store/` | 追加迁移、资源凭据摘要与记录、原子完成连接并建立 Session、恢复查询 |
| `internal/api/` | client／浏览器各自的 HTTP 接口、校验和转换；从 Go 注释生成 Swagger |
| `internal/client/`、`internal/cli/` | 共用服务身份验证，连接与资源管理命令；不直接读数据库或调用钱包 |
| `web/src/wallet/` | Provider 发现、选定实例、EIP-1193 调用及事件处理 |
| `web/src/api/`、页面 | 受保护请求接入、连接呈现与用户操作、结果回传 |

## 钱包发现

- 先注册 `eip6963:announceProvider` 监听，再派发 `eip6963:requestProvider`；页面存活期间持续接收公告，不用短暂扫描窗口断言“所有钱包已发现”。
- 校验公告格式与 Provider 能力；同一 Provider 去重，UUID 冲突不静默覆盖现有选择；迟到钱包加入列表，不自动改变用户选择。
- 另检查符合 EIP-1193 的 `window.ethereum`，未出现在标准列表的实例作为旧式入口；与已有 Provider 同实例时去重。该入口不能保证枚举所有旧式钱包，不依赖品牌私有标记判断能力。
- `name`／`rdns`／图标均来自钱包自报；名称作为文本，图标只按规范的 data URI 图片渲染，不作为 HTML 插入，不加载远程图标。
- 仅发现钱包不调用 `eth_requestAccounts`、切链或其他弹窗方法。React 重挂载、重新发现不重复连接钱包。

PR 2-1 将发现逻辑与 React 选择面板分开：已授权管理页和 Vite 预览显示面板，不默认选中钱包；选择只保存在当前页面内存，退出授权或刷新后重新选择。重复 UUID 的不同实例分别保留并提示冲突，选择用本页内部 ID；旧式实例后续发出标准公告时补充元数据，保留选择。重新检测及窗口聚焦时重新检查旧式入口，不枚举品牌私有字段。

发现测试使用独立 Vite origin 和模拟 Provider，不占用正式服务端口；真实 MetaMask／Fluent 的发现与授权兼容性分开记录。

## 固定钱包的识别边界

EIP-6963 的 UUID 只区分当前页面中的 Provider 会话；`rdns` 用于跨会话提示，但由钱包自报，可能重复或冒用。二者均不是浏览器扩展的可信身份认证。

当前页面绑定选定的 Provider 实例，不因其他公告或 `window.ethereum` 变化而替换。持久 Session 保存用户确认的钱包描述，不能直接把旧 UUID 当成重开页面后的句柄。重新识别或存在歧义时须显式恢复，不能静默改用其他钱包；恢复交互在对应 PR 前细化。

## 连接与状态校验

- 页面依据[请求审阅交互设计](../../approval-flow.md)先展示要求与实际钱包状态；修复不匹配时保留原请求。连接与交易使用各自的动作名称，不把内部 Session 操作作为用户必懂概念。
- 使用 EIP-1193 的 `request` 与账户／网络／断开事件。授权用 `eth_requestAccounts`，查询用 `eth_accounts`／`eth_chainId`；切链请求采用 `wallet_switchEthereumChain`，不自动调用添加网络方法。
- chainId 按整数等值比较，内部使用可避免大数精度损失的表示，Provider 参数使用规范十六进制字符串；账户校验格式并按地址值比较。具体 HTTP 字段随契约 PR 固定。
- 账户或网络事件使当前待确认快照失效；提交前再读实际状态。无论首次连接确认时点如何安排，都不能仅凭一次旧事件或钱包 RPC 成功返回值建立 Session。
- `eth_accounts` 可能返回多个可用账户，不能假定首项就是钱包 UI 当前选中的唯一地址；本轮由用户选择单账户，后续按明确绑定校验。标准可观察范围与 MetaMask／Fluent 的实际行为分别记录。
- 浏览器只提交已获执行权限的请求结果；服务原子检查当前状态、凭据及期限，连接完成与唯一 Session 写入同一事务。具体领取／回传契约在核心流程前设计。
- Session 的绑定一旦建立不随 Provider 事件修改；实际钱包状态与保存绑定分开呈现，后续操作仍需核对。

## 持久化与权限

沿用 SQLite 迁移与受限文件；资源凭据按持有权限隔离，存储摘要，不在页面普通链接或日志中携带。连接完成、取消、关闭与回传幂等须有原子竞争规则。只增加本轮需要的数据，不预建交易表。

### PR 2-2a：连接记录与迁移

- 追加 schema v2，保留 v1 的浏览器授权。`connection_requests` 保存调用方／意图、目标网络、原始创建与到期时间、状态、完成时间和独立凭据摘要；`sessions` 通过唯一外键关联连接，保存固定钱包描述、单账户、chainId、访问／关闭时间及自身凭据摘要。
- Session 钱包描述保存发现方式、名称与 rdns，不把本页 UUID 当成持久身份。chainId 用规范十六进制文本，账户用小写十六进制地址，时间用毫秒；不受浮点数或 SQLite 整数范围限制。
- `internal/app` 定义记录及存储接口；本 PR 只创建待处理连接、按 ID／凭据查询连接和 Session。记录不含原始凭据，凭据摘要只用于存储和匹配，不进入返回模型。
- 连接结果的 Session ID 由唯一关联读取；Session 关闭不删除原连接结果。查询只返回持久记录，不刷新期限或自动调用钱包；活跃检查、回收和恢复协调在后续核心 PR 实现。
- 新数据库及 v1 升级在同一迁移事务内完成，启动时检查新表所需列。完成连接与建立唯一 Session 的事务、终态竞争及迟到回传防护单独在 PR 2-2b 实现；本 PR 不提供独立创建 Session 的方法。

### PR 2-2b：连接原子写入

- 完成与终止方法只供服务内部调用；调用方鉴权和执行归属由后续核心负责，不把存储方法直接暴露给 client。完成参数包含新 Session ID、凭据摘要及钱包／账户／chainId；创建与访问时间由本次服务端时间确定。
- 沿用 SQLite `BEGIN IMMEDIATE` 事务：读取连接、检查状态／期限、写入终态；成功时在同一事务插入唯一 Session。任一步失败全部回滚，ID／摘要冲突不覆盖其他 Session。
- 仅 `pending` 可转为 `succeeded`／`rejected`／`canceled`／`expired`。判断时刻达到原期限则写 `expired`，完成时间为原期限，不创建 Session；未到期不能主动写 `expired`。成功时 chainId 必须等于原请求，钱包及规范化单账户完整有效。
- 同一终态重试返回原记录，不刷新时间；成功回传须保持 Session ID、摘要、钱包、账户和 chainId 一致。不同终态或不同成功内容返回冲突及原记录，不能覆盖结果；成功后的迟到取消也不能关闭 Session。历史成功重试不受原请求期限或 Session 后续关闭影响。
- 测试覆盖事务中断／约束失败回滚、到期边界、取消后迟到成功、相同／冲突回传和并发终态竞争。仍不提供独立创建 Session、关闭／回收、批量到期扫描或外部连接入口。

### PR 2-3a1：生命周期存储

- 复用 schema v2：`last_access_at` 是有效 client 的最后访问时间；`closed_at` 同时标记显式关闭和空闲回收后的失效时间。保留原绑定、摘要与连接结果，不新增状态列或删除历史记录。
- `AccessSession` 在 immediate 事务内按 ID／摘要验证凭据，先判断失效再续期。未失效时访问时间只前进；达到五分钟边界先写入失效时间，不能续期复活。`CloseSession` 使用同一事务规则，重试保留原失效时间。
- `ExpireConnectionsAndSessions` 原子标记到期的待处理连接和空闲 Session，供后续核心在启动／周期维护时调用；失效时间使用原期限。当前没有交易／其他未完成 Session 请求，迭代 3 接入时必须增加未完成请求保护。
- 原始 `Get`／`Find` 查询仍只读、不续期；浏览器查看与原连接结果查询不能调用 `AccessSession`。鉴权失败不触发回收或修改；时钟回退不减少最后访问时间或提前写入关闭时间。
- 本单元只交付存储方法及测试，不启动维护循环，不接入应用流程或正式服务。核心权限／凭据交付、重启调用及 HTTP／CLI 仍由后续 PR 完成。

HTTP 路由、凭据交付、执行归属与恢复规则在相关 PR 前细化；未决点不以代码默认值代替产品决定。
