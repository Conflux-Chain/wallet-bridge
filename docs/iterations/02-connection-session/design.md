# 迭代 2 技术设计草案

状态：2026-11-23，PR 2-1～2-4a 已合并；浏览器执行协调 HTTP 已实现，钱包交接／最终决定待后续 PR。本文沿用[既定架构](../../architecture.md)，不增加模块层级；待定产品行为见 [spec](spec.md)。

## 模块边界

| 模块 | 本轮职责 |
|---|---|
| `internal/app/` | 连接请求与 Session 流程、权限、状态转换、期限及执行协调；定义所需存储接口 |
| `internal/store/` | 追加迁移、连接与 Session 记录、原子完成连接并建立 Session、恢复查询 |
| `internal/api/` | client／浏览器各自的 HTTP 接口、校验和转换；从 Go 注释生成 Swagger |
| `internal/client/`、`internal/cli/` | 共用服务身份验证，连接与资源管理命令；不直接读数据库或调用钱包 |
| `web/src/wallet/` | Provider 发现、选定实例、EIP-1193 调用及事件处理 |
| `web/src/api/`、页面 | 受保护请求接入、连接呈现与用户操作、结果回传 |

## 钱包发现

- 先注册 `eip6963:announceProvider` 监听，再派发 `eip6963:requestProvider`；页面存活期间持续接收公告，不用短暂扫描窗口断言“所有钱包已发现”。
- 校验公告格式与 Provider 能力；同一 Provider 去重，UUID 冲突不静默覆盖现有选择；迟到钱包加入列表，不自动改变用户选择。
- 另检查符合 EIP-1193 的 `window.ethereum`，未出现在标准列表的实例作为旧式入口；与已有 Provider 同实例时去重。该入口不能保证枚举所有旧式钱包，不依赖品牌私有标记判断能力。
- `name`／`rdns`／图标均来自钱包自报；名称作为文本，图标只按规范的 data URI 图片渲染，不作为 HTML 插入，不加载远程图标。
- 仅发现钱包不调用 `eth_requestAccounts`、切链或其他弹窗方法。React 重挂载、重新发现不重复连接钱包。

PR 2-1 将发现逻辑与 React 选择面板分开：已授权管理页和 Vite 预览显示面板，不默认选中钱包；选择只保存在当前页面内存，退出授权或刷新后重新选择。重复 UUID 的不同实例分别保留并提示冲突，选择用本页内部 ID；旧式实例后续发出标准公告时补充元数据，保留选择。重新检测及窗口聚焦时重新检查旧式入口，不枚举品牌私有字段。

发现测试使用独立 Vite origin 和模拟 Provider，不占用正式服务端口；真实 MetaMask／Fluent 的发现与授权兼容性分开记录。

## 固定钱包的识别边界

EIP-6963 的 UUID 只区分当前页面中的 Provider 会话；`rdns` 用于跨会话提示，但由钱包自报，可能重复或冒用。二者均不是浏览器扩展的可信身份认证。

当前页面绑定选定的 Provider 实例，不因其他公告或 `window.ethereum` 变化而替换。持久 Session 保存用户确认的钱包描述，不能直接把旧 UUID 当成重开页面后的句柄。重新识别或存在歧义时须显式恢复，不能静默改用其他钱包；恢复交互在对应 PR 前细化。

## 连接与状态校验

- 页面依据[请求审阅交互设计](../../approval-flow.md)先展示要求与实际钱包状态；修复不匹配时保留原请求。连接与交易使用各自的动作名称，不把内部 Session 操作作为用户必懂概念。
- 使用 EIP-1193 的 `request` 与账户／网络／断开事件。授权用 `eth_requestAccounts`，查询用 `eth_accounts`／`eth_chainId`；切链请求采用 `wallet_switchEthereumChain`，不自动调用添加网络方法。
- chainId 按整数等值比较，内部使用可避免大数精度损失的表示，Provider 参数使用规范十六进制字符串；账户校验格式并按地址值比较。具体 HTTP 字段随契约 PR 固定。
- 账户或网络事件使当前待确认快照失效；提交前再读实际状态。无论首次连接确认时点如何安排，都不能仅凭一次旧事件或钱包 RPC 成功返回值建立 Session。
- `eth_accounts` 可能返回多个可用账户，不能假定首项就是钱包 UI 当前选中的唯一地址；本轮由用户选择单账户，后续按明确绑定校验。标准可观察范围与 MetaMask／Fluent 的实际行为分别记录。
- 浏览器只提交已获执行权限的请求结果；服务原子检查授权、归属、状态及期限，连接完成与唯一 Session 写入同一事务。执行契约见下述 PR 2-3b；HTTP 映射随后补充。
- Session 的绑定一旦建立不随 Provider 事件修改；实际钱包状态与保存绑定分开呈现，后续操作仍需核对。

## 持久化与权限

沿用 SQLite 迁移与受限文件；可信本地 client 共用一份服务凭据，请求／Session 用 UUID 定位。浏览器授权独立保留；连接完成、取消、关闭与回传幂等仍须有原子竞争规则。只增加本轮需要的数据，不预建交易表。

下列 PR 2-2a～2-3a1 记录已合并实现；其中资源凭据部分由 D-034 替代，将在独立迁移 PR 移除。

### PR 2-2a：连接记录与迁移

- 追加 schema v2，保留 v1 的浏览器授权。`connection_requests` 保存调用方／意图、目标网络、原始创建与到期时间、状态、完成时间和独立凭据摘要；`sessions` 通过唯一外键关联连接，保存固定钱包描述、单账户、chainId、访问／关闭时间及自身凭据摘要。
- Session 钱包描述保存发现方式、名称与 rdns，不把本页 UUID 当成持久身份。chainId 用规范十六进制文本，账户用小写十六进制地址，时间用毫秒；不受浮点数或 SQLite 整数范围限制。
- `internal/app` 定义记录及存储接口；本 PR 只创建待处理连接、按 ID／凭据查询连接和 Session。记录不含原始凭据，凭据摘要只用于存储和匹配，不进入返回模型。
- 连接结果的 Session ID 由唯一关联读取；Session 关闭不删除原连接结果。查询只返回持久记录，不刷新期限或自动调用钱包；活跃检查、回收和恢复协调在后续核心 PR 实现。
- 新数据库及 v1 升级在同一迁移事务内完成，启动时检查新表所需列。完成连接与建立唯一 Session 的事务、终态竞争及迟到回传防护单独在 PR 2-2b 实现；本 PR 不提供独立创建 Session 的方法。

### PR 2-2b：连接原子写入

- 完成与终止方法只供服务内部调用；调用方鉴权和执行归属由后续核心负责，不把存储方法直接暴露给 client。完成参数包含新 Session ID、凭据摘要及钱包／账户／chainId；创建与访问时间由本次服务端时间确定。
- 沿用 SQLite `BEGIN IMMEDIATE` 事务：读取连接、检查状态／期限、写入终态；成功时在同一事务插入唯一 Session。任一步失败全部回滚，ID／摘要冲突不覆盖其他 Session。
- 仅 `pending` 可转为 `succeeded`／`rejected`／`canceled`／`expired`。判断时刻达到原期限则写 `expired`，完成时间为原期限，不创建 Session；未到期不能主动写 `expired`。成功时 chainId 必须等于原请求，钱包及规范化单账户完整有效。
- 同一终态重试返回原记录，不刷新时间；成功回传须保持 Session ID、摘要、钱包、账户和 chainId 一致。不同终态或不同成功内容返回冲突及原记录，不能覆盖结果；成功后的迟到取消也不能关闭 Session。历史成功重试不受原请求期限或 Session 后续关闭影响。
- 测试覆盖事务中断／约束失败回滚、到期边界、取消后迟到成功、相同／冲突回传和并发终态竞争。仍不提供独立创建 Session、关闭／回收、批量到期扫描或外部连接入口。

### PR 2-3a1：生命周期存储

- 复用 schema v2：`last_access_at` 是有效 client 的最后访问时间；`closed_at` 同时标记显式关闭和空闲回收后的失效时间。保留原绑定、摘要与连接结果，不新增状态列或删除历史记录。
- `AccessSession` 在 immediate 事务内按 ID／摘要验证凭据，先判断失效再续期。未失效时访问时间只前进；达到五分钟边界先写入失效时间，不能续期复活。`CloseSession` 使用同一事务规则，重试保留原失效时间。
- `ExpireConnectionsAndSessions` 原子标记到期的待处理连接和空闲 Session，供后续核心在启动／周期维护时调用；失效时间使用原期限。当前没有交易／其他未完成 Session 请求，迭代 3 接入时必须增加未完成请求保护。
- 原始 `Get`／`Find` 查询仍只读、不续期；浏览器查看与原连接结果查询不能调用 `AccessSession`。鉴权失败不触发回收或修改；时钟回退不减少最后访问时间或提前写入关闭时间。
- 本单元只交付存储方法及测试，不启动维护循环，不接入应用流程或正式服务。核心权限／凭据交付、重启调用及 HTTP／CLI 仍由后续 PR 完成。

### PR 2-3a2a：单一本机服务凭据

- D-034 替代资源隔离模型：同一系统用户主动运行的本地 client 均可信，共享服务访问和管理能力；不做应用注册或 client 间强隔离。请求／Session 的 ID 不再承担鉴权职责。
- 复用现有 `client.key` 作为唯一服务凭据；新安装只创建这一份。旧 `control.key` 保留原文件以便旧程序正常停止旧服务，新程序不读取、不接受它；不轮换现有服务密钥。
- API 配置、鉴权及共用 client 移除普通／控制角色分支。保留既有 `/control/*` 路由，统一接受服务 Bearer；浏览器 cookie 仍不能调用这些接口，本机 Bearer 不直接代替用户本次同意或钱包确认。
- API 版本为 1.2，公告 `service.auth.shared` capability；新 client 在发送 Bearer 前检查，遇到旧服务明确返回 `incompatible_service`，不尝试旧控制密钥或自动升级。旧程序管理新服务时可能鉴权失败，跨版本管理使用服务配套程序。
- 保留同连接服务证明、Host／Origin 检查和浏览器授权。使用临时数据验证新装单文件、旧密钥复用、旧控制密钥不生效、共享管理能力和版本拒绝；不迁移或重启正在运行的正式服务。
- 此 PR 不改 schema v2；内部存储仍暂有旧资源摘要，无外部连接接口使用它。下一 PR 移除，避免将服务接入和数据库重建放进同一评审单元。

### PR 2-3a2b：移除资源凭据

- 追加 schema v3，保留 v1／v2 迁移原文。在同一事务内建立不含 `token_hash` 的新连接／Session 表、复制记录，先移除旧 Session 表再移除旧连接表，重命名并重建索引；全程启用外键，失败整体回滚。浏览器授权表及摘要不变。
- 沿用现有 128 位 ID 的小写十六进制存储格式；ID 仅定位记录，不承担鉴权。删除独立摘要参数及重复的 `Find` 接口，统一 `Get` 按 ID 查询，创建／完成／访问／关闭仍由上层在授权后调用。
- 成功回传幂等仍核对 Session ID、钱包、账户与 chainId；重复 ID 不覆盖记录。访问／关闭继续使用原事务、期限及历史规则，本 PR 不实现连接 HTTP／CLI 或应用核心。
- 测试覆盖新库、v1／v2 升级与重开，保留全部连接终态及活跃／关闭 Session、浏览器授权、原时间与大 chainId；验证摘要列消失、索引／外键／唯一约束仍有效，以及复制／后续步骤失败回滚。现有终态竞争、提交失败与生命周期测试同步去除旧凭据断言。
- schema v2 程序无法打开 v3；本次测试仅用私有临时数据库，不升级正在运行的正式服务。

### PR 2-3a2c：连接与 Session 核心

- `internal/app` 增加连接流程服务，组合现有事务存储；入口层先完成服务／浏览器鉴权，完成／拒绝方法只供后续已授权且持有执行权的浏览器流程调用。本 PR 不暴露外部接口，也不接入钱包调用。
- D-035：创建输入只含请求 ID、调用方、意图及目标网络；服务生成创建／到期时间。重复 ID 读取并比较不可变输入，相同内容返回原状态和期限，不重置；不同内容返回原记录和冲突。CLI／MCP 的 ID 自动生成及重试复用在接入 PR 实现，不引入本地恢复文件。
- 领域层将十六进制 chainId 规范化，避免大数精度损失；账户统一为小写地址。HTTP／CLI 对十进制输入的转换留给适配层，网络名称仅作原样展示信息，不参与链匹配。
- 完成连接由服务生成 Session ID；重放使用原 ID，并由存储核对完整绑定。并发成功回传若生成了不同 ID，改用已提交 ID 再核对一次；内容冲突仍失败，不续期或重建 Session。
- 查询待处理连接时按原期限原子标记到期；查询原连接结果不访问／续期 Session。Session client 查询调用 `AccessSession`，关闭调用 `CloseSession`，均保留历史。
- 到期维护复用批量事务：新服务在就绪前执行一次，此后每 30 秒执行；查询／写入仍逐次检查期限，后台间隔不构成宽限期。维护失败时服务经正常关闭流程退出并报告存储错误，后续启动可重试；不重置期限、不调用钱包。迭代 3 增加未完成 Session 请求前须补充回收保护。
- 核心测试覆盖响应丢失重试、内容冲突、完成／终止竞争、绑定与结果保留；服务测试用临时目录和随机测试端口验证启动恢复及资源释放。HTTP 路由、执行归属与页面恢复仍在对应 PR 前补充。

### PR 2-3b：连接执行协调

以下是 D-036／037 的实现方案，仅用于本轮连接授权／切链；交易的已发送／结果不确定仍在迭代 3 单独设计。

**记录与归属**

- 沿用 `internal/app` 流程与 `internal/store` 事务，不增加通用任务引擎。schema v4 追加 `connection_executions`，每个连接最多一条当前执行记录；不改既有迁移和请求／Session 期限。
- 记录请求 ID、执行 ID、所属浏览器授权 ID、阶段、最近心跳和最近钱包调用 ID。页面为一次领取／继续及一次钱包交接自动生成 ID，重试复用；这些 ID 用于区分执行，不作为访问凭据，不新增用户文件。
- 一份服务只有一个执行槽，覆盖所有钱包和授权浏览器。SQLite 部分唯一索引约束占用阶段；心跳和页面锁只辅助交互，不能代替事务检查。
- 用户点击连接时领取；同一次领取重试返回原记录，其他页面只读进度。页面离开时尽力上报；丢失时通过心跳识别失联，建议每 10 秒、90 秒失联。节流或网络中断仅意味着须重新确认，不证明页面已关闭；钱包弹窗导致的失焦不算页面离开。心跳不延长请求期限或 Session 空闲时间，刷新等待与后台节流在页面接入时验证。

**阶段**

| 内部阶段 | 含义 | 占用执行槽 |
|---|---|---|
| `ready` | 原页面操作中，无尚未结束的钱包弹窗调用 | 是 |
| `calling` | 已记录钱包交接，可能正在授权／切链 | 是 |
| `interrupted_ready` | 原执行失效，无未结束的交接 | 否 |
| `interrupted_calling` | 原执行失效，钱包调用是否结束尚未确认 | 是 |
| `finished` | 已完成，或已终止且无未结束调用 | 否 |

`ready` 不等于账户／网络已就绪；用户最终同意前，页面仍须按既定流程读取并核对钱包状态。

**钱包交接与结果**

1. 每次可能弹窗的调用前，原子检查浏览器授权仍有效、执行归属、连接状态／期限和调用 ID，将 `ready` 写为 `calling`，提交后才允许调用钱包。已有调用 ID 的重试只查询原交接，不再次授予调用许可。
2. 交接响应丢失时不猜测是否已调用，不自动重入钱包；显示中断并走手动继续。只读钱包查询不产生弹窗交接，但仍须由当前页面执行。
3. 钱包调用结束后按执行／调用 ID 回报；成功、拒绝、错误均表示该调用已经返回。重复回报保持原状态，旧调用的迟到回报不能结束新调用或释放新执行槽。
4. 正常回报回到 `ready`；中断或连接已取消／到期时，回报仅解除等待，不恢复原执行或建立 Session。钱包返回成功也不代替用户最终“同意连接”。
5. 最终同意时，在同一 SQLite 事务检查授权、归属、`ready`、连接期限，写入唯一 Session／连接结果并结束执行；拒绝同理。历史成功重放须属于原执行并匹配绑定，沿用原结果，不因原请求到期而拒绝、不续期。HTTP 不能直接暴露未检查归属的核心完成／拒绝方法。

**中断与继续**

- 关闭／刷新、心跳失联、授权失效或服务重启，使原执行转为对应中断阶段；请求本身仍按原五分钟期限处理。启动恢复在报告就绪前完成，不自动调用钱包。
- 取消／到期时，`ready` 可结束并释放；`calling` 转为 `interrupted_calling`，保留等待。周期回收不能因为请求已是终态便删除这条等待记录。
- 原钱包调用返回可解除等待；授权已失效时不能据旧授权提交结果，须通过当前已授权页面手动处理。
- 用户处理完原页面及钱包弹窗后主动继续：原请求仍有效时，新执行 ID 原子替代旧执行，重新选择钱包并核对；原请求已终止时只解除等待，重新连接须用新请求 ID。原执行的迟到结果不得建立 Session。
- 恢复与完成、取消、到期、调用回报均通过事务竞争；确认中断前已提交的成功结果保留，不回滚 Session。仅查看、重开页面或查询不取得执行权。
- Bridge 不能通过 EIP-1193 强行关闭扩展弹窗，也不能证明弹窗已消失。页面继续按钮需明确提示用户先结束原操作；不承诺跨浏览器／进程的“恰好调用一次”。

**验证边界**

存储测试覆盖唯一执行槽、重复领取／交接／回报、原子回滚、恢复后旧执行拒绝、取消／到期保留等待以及终态并发；核心与服务测试覆盖心跳、授权失效、重启和无自动钱包调用。HTTP／页面接入后再用模拟 Provider 验证实际调用次数、双页面和交接丢包；真实钱包兼容性仍单独验收。

#### PR 2-3b1：执行记录与领取存储

- 追加 schema v4 及所需领域记录／存储接口，只提供只读查询、领取、心跳、主动中断、显式恢复和批量中断维护。`calling` 阶段先具备存储约束，交接／回报写入留给下一 PR。
- 领取／恢复／心跳的事务先验证调用层传入的浏览器主体仍有效；执行 ID 必须为每次新操作生成的新 ID，重试复用。相同领取／恢复重试返回原记录但不续心跳；恢复核对原执行 ID，新执行替换后旧 ID 不能再心跳或中断。
- 固定心跳失联阈值为 90 秒，达到边界不能通过续心跳复活；访问时间只前进。普通维护按期限、授权或失联标记中断，启动中断另有明确方法；本 PR 尚不接入服务定时器。
- 请求终止时，无未结束调用可标 `finished`；有调用则保留 `interrupted_calling` 和单槽占用。显式恢复对有效请求建立新执行，对终止请求只解除等待；与其他领取竞争仍由事务／唯一索引决定，不改请求和 Session 记录。
- 验证使用临时 SQLite，多数据库连接竞争及触发器／提交失败注入；不新增钱包调用、外部接口或页面操作。

#### PR 2-3b2：钱包交接与终态存储

- 复用 schema v4，增加交接／回报及受执行归属保护的完成／拒绝方法；浏览器主体校验、执行检查、连接终态、唯一 Session 和执行结束均处于同一 immediate 事务。提取原连接转换的事务内函数共用，不增加外层模块。
- 交接输入为执行归属、全新调用 ID 和预期上一调用 ID（首次为空）。仅当前 `ready` 且请求有效、上一 ID 一致时写为 `calling`，提交成功后返回一次调用许可；同调用重试返回记录但不再许可。返回后保留最近调用 ID，旧交接即使延迟到下一调用结束后，也因上一 ID 不匹配而拒绝，不新增调用历史表。
- 回报只表示授权／切链调用已经返回，不提交账户或连接结果。核对执行与调用 ID；正常回到 `ready`，中断后只转为 `interrupted_ready`，终止／到期则 `finished`。重复回报不续心跳、旧调用不能结束新调用，原授权失效须由当前授权页手动处理。
- 最终完成／拒绝要求当前 `ready`、有效浏览器授权及有效请求；到期可持久化 `expired`，仍保留未结束调用的等待。终态重放只接受原执行及相同结果；Session 关闭后重放不复活。未受执行保护的原核心方法仍只供内部使用，外部接入必须走受保护方法。
- 测试使用真实临时 SQLite 验证重试许可、延迟请求、跨连接竞争、执行替换、期限／授权及逐步写入／提交回滚。服务协调、HTTP 和真实钱包调用仍由后续 PR 交付。

#### PR 2-3b3：协调核心接入

- 扩展现有 `ConnectionService`，组合连接与执行存储，不增加目录或任务引擎。浏览器方法独立接收已认证的 `BrowserGrant` 和仅含请求／执行 ID 的输入，归属中的授权 ID 由核心填入；适配层负责认证主体，写入事务再次检查授权有效性。
- 提供执行查询、领取／心跳／中断／恢复、钱包交接／回报及受归属保护的完成／拒绝。查询不续期、不取得执行权；浏览器完成先规范化绑定，生成／复用 Session ID，竞争时复用已提交 ID 再核对。旧的按请求 ID 完成／拒绝仍仅供内部使用，HTTP 不得映射到它们。
- 连接取消／到期等终态与执行中断在同一事务协调；未结束调用保留等待。统一维护在一个 SQLite 事务内处理连接到期、Session 回收及执行阶段，失败整体回滚，不改变 schema v4。
- 服务就绪前统一恢复，显式中断原执行；每 30 秒统一维护心跳、授权及期限，查询／写入仍逐次检查期限。普通打开第二个存储连接不触发重启恢复；没有自动钱包调用或队列调度。
- 维护仍设五秒超时；失败沿正常关闭路径释放 HTTP、数据库及服务锁并报告 `storage_error`。测试用临时时钟／数据和随机端口验证恢复在就绪前完成、等待保留、故障回滚及清除故障后重启；正式服务不升级或重启。

### PR 2-4a：client HTTP 接入

本单元仅将已有连接／Session 核心映射到 HTTP；浏览器执行接口、共用 Go client、命令和页面分别交付。

| 方法与路径（均在 `/api/v1` 下） | 核心方法 | 成功响应 |
|---|---|---|
| `POST /connections` | `Create` | 200，原连接快照；新建与相同内容重试一致 |
| `GET /connections/{id}` | `Get` | 200，连接状态及可选 Session ID；不续期 Session |
| `POST /connections/{id}/cancel` | `Cancel` | 200，已取消快照；终态竞争返回 409，随后查询原记录 |
| `GET /sessions/{id}` | `Session` | 200，绑定、访问／关闭时间及 active／closed；仅有效访问续期 |
| `POST /sessions/{id}/close` | `CloseSession` | 200，失效 Session 历史；重复关闭不改时间 |

- 五个入口仅接受服务 Bearer；cookie 不能创建／取消连接、续期／关闭 Session，更不能凭服务令牌建立 Session。继续沿用全局 Host／Origin 检查，不开启 CORS。
- JSON 输入沿用 camelCase；创建字段为 `id`、`clientName`、可选 `intent`、`chainId`、可选 `chainName`。ID 继续使用 32 位小写十六进制；chainId 必须是十进制或 `0x` 十六进制字符串，以整数等值规范化输出，禁止 JSON 数字及浮点转换。
- 创建 body 限 8 KiB；取消／关闭继续限 1 KiB，可为空或 `{}`。拒绝未知字段、尾随 JSON 及 query；读取不接受 body 或 query。期限与状态由服务生成，不能由 body 指定。
- 连接响应包含原输入、状态、创建／到期／可选完成时间及 `sessionId`；取得 Session 后显式访问其接口获取固定钱包／账户／网络。不在本单元返回尚未实现的页面链接。
- 参数错误 400、无认证 401、Host／Origin 403、资源不存在 404、方法错误 405、状态／内容冲突 409、body 超限 413、媒体类型 415、存储失败 500。错误只含稳定 code／message，不回传存储细节；冲突后查询原 ID 对账。
- API minor 升为 1.3，新增 `connections.lifecycle` capability；不改变已有接口或 schema v4。共用 client 的新能力检查在 PR 2-4c 接入，现有服务管理仍兼容。
- 在 handler 注释维护契约并生成 `docs/swagger`；真实临时 SQLite／随机端口验证鉴权、创建重试、终态、到期、历史、续期及存储失败时不误报成功或泄露细节。正式服务不升级或重启。

### PR 2-4b1：浏览器执行协调 HTTP

将已有核心映射到 `/api/v1/browser/connections/{id}`，本单元不接入钱包交接、最终决定或页面操作。

| 方法与路径后缀 | 核心方法 | 输入／响应 |
|---|---|---|
| `GET` 原路径 | `Get` | 连接快照；不访问／续期 Session |
| `GET /execution` | `Execution` | 当前执行；尚无执行返回 404 |
| `POST /execution/claim` | `ClaimExecution` | `{id}` 为新执行 ID；200 返回原子领取结果 |
| `POST /execution/heartbeat` | `TouchExecution` | `{id}`；只续仍有效执行的心跳 |
| `POST /execution/interrupt` | `InterruptExecution` | `{id}`；中断原执行，不取消连接或撤回钱包调用 |
| `POST /execution/recover` | `RecoverExecution` | `{id, previousId}`；显式恢复需新 ID，并核对旧 ID |

- 六个入口均要求固定 Host 和有效管理 cookie。浏览器同源 GET 可以省略 Origin。提供的 Origin 必须唯一且精确匹配，四个 POST 必须提供 Origin。Bearer 不能替代 cookie；同时携带 Bearer 时仍按 cookie 认证。授权主体由 HTTP 层认证后单独传入核心，不接受 body 提供的授权 ID。写事务再次检查授权，防止认证后撤销仍写入。
- 复用 client HTTP 的 ID 格式、时间格式、读入参拒绝与 1 KiB 控制 body 限制；只接受所列字段。执行响应仅含 `connectionId`、`id`、`phase`、`lastSeenAt` 和可选 `callId`，不返回浏览器授权 ID、cookie 或摘要。
- 读取不领取、不续心跳或 Session；执行快照不主动归一化阶段，受心跳／期限影响的写入仍由核心当场检查。页面不能凭一次旧快照直接调用钱包；后续交接接口会逐次核验。
- 相同领取／恢复重试保留原心跳；其他页面可观察进度，但不能借 body 中的授权 ID 修改归属。恢复由页面显式动作发起；请求已终止时只释放等待并返回原执行的 `finished`，不保证安装 body 中的新 ID，更不建立 Session。
- 缺失／到期／撤销 cookie 为 401，Origin 不符为 403；无执行 404，执行归属／阶段或单槽占用 409。其余沿用 client HTTP 错误映射；409 后重新查询原连接和执行，不自动换 ID 重领。
- API minor 升为 1.4，新增 `browser.connections.coordination` capability；schema v4、client 侧权限和服务生命周期不变。Swagger 随 handler 注释生成；使用真实临时 SQLite、随机端口 HTTP 验证认证、重放、竞争、中断恢复、期限、撤销和存储失败。
