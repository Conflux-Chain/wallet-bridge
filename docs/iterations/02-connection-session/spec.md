# 迭代 2：连接钱包与 Session

状态：2026-11-20 PR 2-1～2-3a2c 已合并；执行协调行为已确认，方案待评审。沿用[需求基线 §5、8～9](../../requirements.md#5-连接钱包与-session)，方案与拆分见 [design](design.md)、[plan](plan.md)。

## 目标与边界

交付 CLI／HTTP 连接请求、标准钱包发现、钱包与单账户选择、按目标 chainId 切链、固定 Session、查询／取消／关闭及本轮持久化与恢复。关联 A-04～07、11～12、16～17；不含交易、消息签名、业务 RPC 或 MCP tool。

沿用 Windows amd64、macOS amd64／arm64 与 Chrome；真实钱包验收 MetaMask、Fluent 的 EVM／Conflux eSpace。迭代 1 的缺失环境保留在[验收记录](../01-local-service/acceptance.md)，不计作已验收。

## 已确认与沿用

| 项目 | 要求 |
|---|---|
| Session 绑定 | 用户于 2026-11-20 确认固定本次选择的钱包、一个账户与 chainId；换钱包新建 Session |
| 本次同意 | 已有浏览器管理授权或钱包对本站的授权，均不等于同意本次 client 连接 |
| 同意时点 | 先完成必要的钱包授权／切链，再展示最终钱包、单账户和目标网络，用户点击“同意连接”才建立 Session；已有站点授权可直接选择账户并同意 |
| 取消／到期 | 即使已进入钱包授权／切链，连接取消或创建满五分钟后也不再建立 Session；迟到成功不恢复请求，需要新建连接；钱包已发生的变化不自动回滚 |
| 网络 | client 必须指定 chainId；名称仅用于展示；不自动添加网络，不要求 client 提供 RPC |
| 账户 | 用户明确选择一个；钱包返回多个时不能默认拿第一个建立 Session |
| 权限 | 同一系统用户主动运行的本地 client 视为可信，共用一份自动管理的服务凭据；请求／Session 仅按 UUID 定位，不承诺 client 间安全隔离；管理页仍需浏览器授权，普通请求链接不携带审批权限 |
| 生命周期 | 沿用创建起默认五分钟的请求期限、无未完成请求时五分钟无 client 访问的 Session 回收，以及显式关闭规则 |
| 历史查询 | 关闭／空闲回收后，可信 client 可按 ID 查询失效状态、固定绑定及已完成连接结果；禁止继续发起钱包操作 |
| 续期 | 本轮仅 client 查询有效 Session 时续期；原连接结果查询、浏览器查看均不续期，失效查询不能复活 |
| 恢复 | 保存绑定、原期限与结果；关闭页面不取消请求；重启、查询和恢复均不自动调用钱包 |
| 创建重试 | Client 自动为一次连接生成请求 ID 并在重试时复用；相同 ID／内容返回原请求及原期限，内容不同报冲突；取消／到期后新建连接须用新 ID。不增加凭据或恢复文件（D-035） |
| 多页面 | 一次只处理一个钱包连接操作；原页面正常操作时，其他页面展示进度，不调用钱包（D-036／037） |
| 中断继续 | 页面刷新／关闭或服务重启后，原请求仍有效时，用户可点击“继续连接”，重新选择钱包并核对账户／网络；不自动弹窗，原执行的迟到结果不建立 Session（D-036） |
| 钱包调用未结束 | 即使请求已取消／到期，其他请求仍等待原授权／切链调用返回；或由用户处理完原弹窗后主动继续。取消请求不等于钱包调用已撤回（D-037） |

## 页面交互基线（已确认）

用户于 2026-11-20 确认[请求审阅与钱包确认流程](../../approval-flow.md)。连接页沿用先展示来源与要求、对比实际钱包状态、在原页修复不匹配的原则；使用“连接钱包”“同意连接”等动作，Session 由系统管理。

交易页的每笔确认不代替本次连接同意。2026-11-20 用户确认上述同意时点及取消／到期规则；这两项适用于连接，不改变交易发送后的不确定结果规则。

## 后续 PR 前再细化

- 核心：创建重试已按 D-035 确认；单服务凭据及资源凭据移除按 D-034 完成，不再设计资源令牌交付／恢复。
- 执行协调：多页／中断／钱包等待行为已按 D-036／037 确认；技术协议见 design。队列展示及请求选择顺序在页面集成前细化，不在本次引入自动调度。
- HTTP／CLI 前：将已确认的请求 ID 重试规则映射为具体字段、命令选项、等待／退出码和链接打开行为；client 名称仍为自报信息。
- 页面集成前：切链不支持／用户拒绝的恢复提示、重开页面后的钱包重新识别与执行归属。

这些条目是开发前检查点；未定行为不在当前方案中默认为已确认，也不阻止独立的钱包发现设计。

## 验收重点

| 场景 | 预期 |
|---|---|
| 多钱包 | 标准发现、迟到公告、重复公告与旧式 Provider 可处理；用户明确选择，不按品牌白名单过滤 |
| 连接 | 每次连接同意明确，返回正确钱包选择、单账户及目标网络的 Session；未知网络／拒绝／账户变化不误报成功 |
| 接入与并发 | 无服务凭据不能调用本机受保护接口；普通请求 ID 不授予浏览器审批权；重复点击、多页、回传重试不创建重复 Session 或重入钱包 |
| 存储升级 | 已有连接／Session 可不带资源令牌按 ID 查询；迁移保留原结果、绑定、期限、浏览器授权和已关闭历史，失败不留下部分升级 |
| 生命周期 | 查询／取消／关闭与期限、重启规则一致；Session 绑定不可修改，过期不重置，恢复不自动调用钱包 |
| 执行中断 | 多页不能并行领取；刷新／重启后手动继续，原执行迟到回传不能建 Session；心跳丢失、请求取消／到期均不证明钱包调用结束 |

模拟 Provider、实际钱包连接及用户验收分别记录；本轮不发起签名或链上交易。
