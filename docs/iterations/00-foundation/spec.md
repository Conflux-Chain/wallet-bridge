# 迭代 0：范围与方案

状态：2026-11-19 范围与技术方向已确认，文档已通过 PR 交付，记录见 [plan](plan.md)。依据[需求基线](../../requirements.md)与[路线图](../../roadmap.md)，技术设计见 [design](design.md)。

## 目标与范围

明确首批支持矩阵、首版交付入口、可选能力范围，作为技术选型与后续迭代的依据。本轮交付文档，不实现钱包功能。

| S0-02 | 交付入口 | 已确认 CLI／HTTP／MCP，首批 agent 为 Codex，见需求基线 §2；命令和 tool 在对应迭代细化 |

## 钱包兼容方向

- 通用接入不依赖 MetaMask 专有标识；具体钱包的连接、切链与发送能力分别验证。
- 技术提案：以 [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193) 为 Provider 接口基础，以 [EIP-6963](https://eips.ethereum.org/EIPS/eip-6963) 发现多钱包并供用户选择；旧式注入兼容方式在 design 中细化。
- Fluent 的公开 [dev 源码](https://github.com/Conflux-Chain/helios/blob/dev/packages/inpage/setup-inpage-provider.js)已实现 EIP-6963 广播；发布版本与 EVM 操作仍需实测。

## 设计与后续待细化

- 技术栈、工程结构、MCP 打包形态、访问隔离及原生发行架构已在 PR 0-2 的 [design](design.md) 记录。
- 最低系统版本在迭代 1 的相关实现前明确；WSL／容器兼容范围及钱包版本仍需细化，“同机运行”不自动确定这些兼容性。
- 具体命令、tool、交易字段及状态协议按对应迭代细化。

## 验收条件

- PR 0-1：S0-01～03 结论与需求基线一致，首版与后续范围清楚，文档引用有效。
- PR 0-2：设计覆盖语言、工程结构、钱包接入、打包及权限边界；未决细节关联后续迭代。
- 按 PR 计划分别交付范围与设计，不提前实现功能。

本轮验收不代表钱包、链上交易或 agent 已完成真实环境验证。
