# 迭代 1：本地服务

状态：2026-11-19 已确认。沿用[需求基线](../../requirements.md)和[迭代 0 设计](../00-foundation/design.md)；技术细节见 [design](design.md)，交付与验收进度见 [plan](plan.md)。

## 1. 目标与边界

交付可独立运行的本地服务：固定 origin、单实例常驻、启动／复用／就绪检查、版本兼容判断、页面入口及基础访问控制。关联验收 A-01～04。

本轮页面用于服务状态与浏览器授权；钱包发现、连接、Session、交易及 MCP tool 按后续迭代交付。A-04 本轮验证服务接入、控制与浏览器权限，按请求／Session 隔离在迭代 2～4 补齐。

## 3. 使用行为

- 服务与数据归当前操作系统用户；同用户的 CLI／HTTP／MCP client 共用服务，不要求管理员权限或应用注册。其他系统用户不自动获得访问权限。
- `service ensure` 启动或复用服务，不打开浏览器；成功前必须完成就绪与兼容检查。并发调用允许短暂存在候选进程，只有一个有效服务。
- `service status` 只查询，不拉起服务；`service stop` 要求本机控制权限。调用者退出不停止服务，主动停止后允许再次启动。
- 端口占用、无法确认服务身份、接口不兼容、权限错误、启动超时分别返回明确错误；不换端口、不抢占其他进程、不在接入时自动升级或降级。
- `ui` 确保服务就绪，通过本机控制权限打开一次性浏览器授权链接。可显式选择只输出链接；普通状态输出和诊断日志不包含授权链接或凭据。
- 未授权浏览器可以加载通用授权说明页，不能读取管理数据或执行管理操作。授权成功后可查看本轮服务状态；授权到期或主动撤销后须重新授权。
- 30 天从授权成功时起算，不因查询或重启延长。撤销只使浏览器管理凭据失效，不删除业务记录；已在钱包中的操作如何处理在交易迭代细化。

## 4. 本轮验收

| 场景 | 预期 | 关联 |
|---|---|---|
| 独立程序启动 | 三个原生目标可构建并运行，内含页面；用户不依赖 Go／Node.js。各系统真实运行与最低版本证据分别记录 | A-01 |
| 并发启动与常驻 | 多进程同时 ensure 只产生一个有效服务；兼容服务被复用；client 退出后服务仍可查询 | A-02 |
| 锁、占用与恢复 | 非本服务占端口、已有实例启动中、异常退出后的重启正确区分；不按旧 PID 盲目终止进程 | A-02～03 |
| 版本与就绪 | 区分发行版本、接口版本及能力；不兼容明确失败，就绪超时不报告启动成功 | A-03 |
| 本机权限 | 数据与凭据对其他普通系统用户不可读；无法建立必要权限时启动失败。普通 client 凭据不能停止服务或签发浏览器授权 | A-04 |
| 浏览器授权 | 一次性链接过期或重放被拒绝；授权可跨服务重启，30 天到期及主动撤销生效；不同浏览器配置独立授权 | A-04 |
| HTTP 访问边界 | 错误 Host／Origin、跨站页面、缺失或错误凭据不能获得管理权限；响应与日志不泄露凭据 | A-04 |

未完成的平台、浏览器或故障测试明确记为待验证，不能以交叉编译成功代替真实运行证据。
