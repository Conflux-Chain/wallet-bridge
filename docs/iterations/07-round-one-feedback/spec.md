# 迭代 7 · 第 1 轮体验反馈

原始现象、用户决定和已验证环境见[第 1 轮记录](../../local-trials/v0.1.0/round-01/feedback.md)。本轮按以下条件复测。

| 反馈 | 验收条件 |
|---|---|
| 1、2 · 交易 Session | `transaction send` 缺少 Session ID 或格式有误时，指出 `--session-id`、有效格式及取得 ID 的命令。保留退出码 2 和脚本可读的 JSON 错误。用户用有效 ID 复测后再讨论省略选项。 |
| 5 · CLI 自助使用 | 从顶层帮助找到命令用途，从子命令帮助识别参数含义、必填项和省略时的行为。典型错误指出失败原因与可执行的纠正步骤。 |
| 3、4 · Git Bash | 在新的 Windows Git Bash 终端按指南运行候选程序，定位 Codex CLI、完成 MCP 注册并核对路径。用户已确认以 Git Bash 实测验收。 |
| 6 · 审批链接 | 在 macOS Codex 中点击连接或交易的审批链接，在装有插件钱包的系统默认浏览器继续原请求。核对请求 ID、授权边界和审批次数。若 Codex 打开内置浏览器，用户可在页面一键转到系统默认浏览器。MCP 返回链接时一并提示。 |
| 6 · 首次使用或浏览器授权到期 | 分别从 CLI 和 Codex 发起连接、发送交易、查看历史。每项操作都可在原流程内完成，期间无需另行运行 `wallet-bridge ui` 或向 agent 确认浏览器授权。 |
| 6 · 原请求与操作范围 | 从 Codex 内置浏览器转到钱包浏览器后继续原 ID 的审批。核对账户与网络后由用户同意连接，交易在钱包中确认。单笔审批入口仅能处理本次请求。 |
| 6 · 跨浏览器配置 | 将完整审批链接复制到同机另一个全新配置，可以核对、处理或拒绝原请求。仅持该链接不能列出历史或审批其他请求。两处打开仍只产生一个结果，原期限届满后不能再发起审批。 |
| 6 · 查看历史 | 在没有活动 Session 和钱包插件的环境查看已有记录，也能识别空历史。整个流程不触发钱包调用。 |

本轮交付本地候选与按反馈编号组织的复测步骤。公开发行由用户体验后另行确认。
