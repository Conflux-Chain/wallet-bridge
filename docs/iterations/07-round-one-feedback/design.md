### 反馈 6 · 从可信入口完成原操作

**已确认的产品行为。** 用户在 CLI 或 Codex 中发起操作即表达了访问目的。Bridge 负责衔接访问，用户只需核对并同意连接、在钱包里确认交易，或直接查看所请求的历史。首次使用、授权到期与请求间的访问边界见[验收条件](spec.md)。

**当前缺口。** CLI 与 MCP 已能凭本机服务凭据创建请求。#104 可以打开原请求，但新浏览器配置仍会被引导去终端授权。现有活动列表通过浏览器管理 cookie 读取，CLI 和 MCP 尚无历史列表入口。

**已确认的链接范围。** 持有 CLI 或 Codex 给出的完整审批链接，可在同机另一浏览器配置内审阅或拒绝这一笔请求。仅含 ID 的地址只用于定位。复制、刷新、在默认浏览器继续均沿用原 ID 和期限。过期或已结束的请求不能借此重新审批，已交给钱包的交易仍按原执行接收结果。

**实现方向。** 由可信 client 取得单笔审批链接，服务按请求类别、ID、期限及当前状态核验可执行的操作。各配置沿用现有的钱包操作互斥规则。查看历史使用独立的只读入口，复用活动记录查询和分页规则。

### 反馈 5 · 连接时的网络参数

**已确认。** `connect` 曾将链 ID 与其他参数一起校验，失败就打印用法。缺少 `--chain-id` 时指出缺参，格式错误时指出该字段并给出十进制 `71`、十六进制 `0x47` 两个例子。两类错误都在启动服务前写入 stderr，退出 2。使用 `--json` 时返回 `bad_request`。

### 反馈 5 · 管理命令的 ID

**已确认。** 连接、Session 和交易的管理命令共用一段位置参数校验。缺少 ID、格式有误、多给 ID 时分别说明原因，并提示只传一个 32 位小写十六进制 ID。连接请求 ID 来自 `connect`，Session ID 来自批准连接后的结果，交易请求 ID 来自 `transaction send`。错误写入 stderr，退出 2，`--json` 返回 `bad_request`。

### 反馈 5 · 其余命令行参数错误

**已确认。** 公共参数和子命令各自校验，过去多个失败分支直接打印用法。相对数据目录、空调用方名称、未知选项、多余参数、浏览器分页／撤销和下载版本等错误，应指出出错位置及修正方法。沿用文本和 JSON 输出、stderr 及退出码，用打包 CLI 自动验收。
