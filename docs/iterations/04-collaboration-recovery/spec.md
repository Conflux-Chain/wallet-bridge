# 迭代 4 · 协作与恢复

已确认：管理页按创建时间从早到晚列出各 client 的待审批连接与交易。钱包空闲时，用户可以先处理后到的请求。一项操作已占用钱包时，其他请求沿用现有等待与恢复流程。[D-060](../../decisions.md) · [单笔交易规则](../03-single-transaction/spec.md#钱包弹窗与重启)

列表只用于找回原请求。读取列表不会占用钱包、续期或触发钱包调用。到达原审批期限、完成、取消、拒绝或已交给钱包发送的请求退出待审批列表。占用钱包的未返回调用仍可从管理页现有占用提示找回。

## 活动记录

每个连接或交易请求自创建起有一条活动记录，最近创建的排在前面。重试、状态变化和迟到的交易哈希都更新原记录，排序位置由创建时间决定。关闭或回收 Session 后仍可查看已有活动。[D-061](../../decisions.md) · [需求 §9](../../requirements.md#9-持久化日志与重启恢复)

清理活动时历史查询、去重与迟到结果的保留范围留到 4-5 确认。[验收项 A-04、10～12、14～17](../../acceptance.md)
